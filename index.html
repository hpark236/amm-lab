The sandwich

04 · LP economics

Impermanent loss

An LP's position rebalances against every price move, so it always ends up holding more of whatever fell. Versus simply holding, the LP is down 2√r / (1 + r) − 1 at price ratio r. Fees have to outrun that.

05 · on-chain

MiniPair.sol

A Uniswap-V2-style pool written in Solidity 0.8: LP shares minted at √(x·y) with locked minimum liquidity, a 0.30% fee that compounds into k, slippage and deadline guards, reentrancy protection and an invariant assert on every swap.

The Hardhat suite imports this page's math library and replays the sandwich against the real contract. The attacker's on-chain profit equals the browser's prediction exactly.

mints √(x·y) shares on first deposit and locks the minimum
prices a swap exactly like the JavaScript model
grows k with fees, so LPs earn on round trips
reverts when slippage exceeds the caller limit
rejects unknown tokens, zero input and stale deadlines
extracts exactly the profit the model predicts (2% slippage)
a 0.1% limit cuts the extractable value by more than 10x
over-sized front-runs make the victim revert instead of overpaying
function swapExactIn(address tokenIn, uint256 amountIn,
    uint256 minOut, address to, uint256 deadline)
    external nonReentrant beforeDeadline(deadline)
    returns (uint256 amountOut)
{
    bool zeroForOne;
    if (tokenIn == address(token0)) zeroForOne = true;
    else if (tokenIn != address(token1)) revert InvalidToken();

    (uint256 rIn, uint256 rOut) = zeroForOne
        ? (reserve0, reserve1) : (reserve1, reserve0);
    amountOut = getAmountOut(amountIn, rIn, rOut);
    // the caller's slippage limit is the sandwich's ceiling
    if (amountOut < minOut) revert InsufficientOutput(amountOut, minOut);

    uint256 kBefore = uint256(reserve0) * reserve1;
    IERC20(tokenIn).safeTransferFrom(msg.sender, address(this), amountIn);
    (zeroForOne ? token1 : token0).safeTransfer(to, amountOut);
    _sync();
    assert(uint256(reserve0) * reserve1 >= kBefore); // k never shrinks
    emit Swap(msg.sender, tokenIn, amountIn, amountOut, to);
}
